# Project Charter

## Project Name
Campus Queue Management Web App

## Project Description
The Campus Queue Management Web App is a web-based solution designed to help students and campus service staff manage service queues more efficiently. The app enables students to select a campus service, join a virtual queue, monitor their queue position and estimated waiting time, and receive notifications when their turn approaches. Staff can manage the queue, call the next student, track service completion, and update queue status in real time.

## Project Goal
Create a simple and user-friendly digital queue management platform for campus services such as the cafeteria, printing shop, student services, and library. The primary goal is to reduce physical waiting lines, improve queue visibility, and make the student service experience more efficient.

## Problem Statement
Students often wait in physical lines for campus services. This can lead to long wait times, unclear queue visibility, and inconsistent staff coordination. The campus needs a digital queue system that reduces congestion and improves service delivery.

## Objectives
- Provide students with an easy way to select a campus service.
- Let students join and manage a virtual queue online.
- Display live queue status and estimated waiting time.
- Notify students when their turn is approaching or ready.
- Allow staff to manage and update the service queue.
- Improve service efficiency across campus departments.

## Scope

### In Scope
- Service selection for campus departments such as Cafeteria, Printing Shop, Student Services, and Library.
- Queue status view showing number of people waiting and estimated wait time.
- Virtual queue joining and leaving.
- Digital queue number and current queue position.
- Notifications for queue progress.
- Staff queue management tools to call the next student, complete service, and update status.

### Out of Scope
- Payment integration for cafeteria or printing services.
- Student authentication and role-based permissions beyond basic staff/student views.
- Real-time messaging across multiple departments beyond the MVP.
- Full analytics dashboard or advanced reporting.

## MVP Features

### Service Selection
The system should allow users to view available campus services, including:
- Cafeteria
- Printing shop
- Student services
- Library

Users can select a service to check queue status.

### Queue Status & Waiting Time
The app should display:
- Current number of people waiting.
- Estimated waiting time.
- Current queue status and service availability.

### Virtual Queue
Students should be able to:
- Join a queue through the website without physically standing in line.
- Receive a digital queue number.
- View their current position in the queue.
- Leave the queue if needed.

### Queue Notifications
The app should notify users when:
- Their turn is approaching.
- It is their turn to be served.

### Staff Queue Management
Staff members should be able to:
- View the current waiting list.
- Call the next student in the queue.
- Mark a student's service as completed.
- Update queue status.

## Stakeholders

### Primary Users
- Students using campus services.
- Service staff managing queues.

### Supporting Stakeholders
- Campus administration.
- Student affairs or service department managers.
- Web application development team.

## User Roles

### Student
A student can choose a service, join a queue, view queue position, and receive notifications.

### Staff
A staff member can manage the waiting list, call the next person, complete service requests, and update queue state.

## Functional Requirements
1. The system must show available campus services and service descriptions.
2. The student must be able to join a virtual queue for a selected service.
3. The system must provide the student with a queue number.
4. The system must show the current number of people in the queue.
5. The system must estimate the waiting time for the selected queue.
6. The system must notify the student near their turn.
7. The staff must be able to manage service progress from the current queue.
8. The system must allow staff to call the next student and mark the service as complete.

## Non-Functional Requirements
- The web app should be responsive and accessible on desktop and mobile devices.
- The interface should be easy to use for students and staff.
- The app should provide quick queue updates and clear service information.
- The system should be reliable enough for daily campus service operations.

## Project Timeline

### Phase 1: Discovery & Design
- Define services and queue workflow.
- Create user interface design and project requirements.

### Phase 2: MVP Development
- Implement service selection.
- Implement virtual queue and queue number flow.
- Implement waiting list and staff actions.
- Add notification handling.

### Phase 3: Testing & Launch
- Test all core user flows.
- Validate queue status and staff operations.
- Launch the MVP for selected campus services.

## Risks
- Low user adoption if the app is not intuitive.
- Service departments may have different queue processes.
- Staff may need training to use the queue management interface.
- High demand may require scaling and updated service estimates.

## Success Metrics
- Students can join a queue in less than one minute.
- Staff can call and complete service requests efficiently.
- Average queue wait time is reduced.
- User satisfaction improves for campus services.

## Project Approval
This charter defines the initial scope, objectives, and MVP requirements for the Campus Queue Management Web App. It should be reviewed and approved by the project sponsor, campus service stakeholders, and project team before development begins.
